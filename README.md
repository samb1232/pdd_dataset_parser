# PDD Dataset Parser

This repository contains different parsers for the **Puzzle-Driven Development (PDD)** XML dataset, extracted from the **0pdd** tool. The dataset consists of puzzles generated from in-code comments.

## Parsers

### `parser_xml.rb`
Scans a directory of XML files (from `./data/0pdd-dataset`), parses each file using REXML, and extracts puzzle-related data into a JSON array.

**Key features:**
- Filters files to process only `.xml`.
- Extracts: `project_link`, `issue_link`, `ticket`, `id`, `created_at`, `closed_at`, `done`, `body`, `file`, and `lines`.
- Checks project visibility before including puzzles.
- Output: `puzzle_related_data_from_xml.json` (flat puzzle list).

---

### `parser_append_info_from_github_api.rb`
Enriches the flat puzzle list with metadata from the GitHub API (formerly `enrich_tickets_from_file.rb`).

**Key features:**
- Reads `res/puzzle_related_data_from_xml.json`.
- Fetches `labels`, `assignees`, `title`, `comments`, `issue_events`, and `flags` from GitHub.
- Uses a checkpoint system (`enrich_tickets_checkpoint.json`) to safely resume interrupted tasks.
- Output: `enriched_tickets.json`.

---

### `parser_split_by_project.rb`
Groups enriched puzzles by their respective GitHub project and prepares them for per-project analysis.

**Key features:**
- Reads `enriched_tickets.json`.
- Flattens the nested `github` metadata into the top-level issue object.
- Filters out projects with fewer than 8 issues.
- Output: Multiple JSON files in `pdd_issues_split_by_project/` (one per repository).

---

### `enrich_projects.rb`
Enriches project-specific JSON files with additional repository metadata from the GitHub API.

**Key features:**
- Reads JSON files generated by `parser_split_by_project.rb` from `res/pdd_issues_split_by_project/`.
- Fetches `language`, `stars`, `forks`, and precise contributors count using the GitHub API.
- Recommends using the `GITHUB_TOKEN` environment variable to avoid API rate limits.
- Output: Enriched JSON files in `res/pdd_issues_split_enrich/`.

---

### `calculate_issue_stats.rb`
Calculates statistics for issues and projects based on the enriched GitHub data.

**Key features:**
- Reads JSON files from `res/pdd_issues_split_enrich/` (or falls back to `res/pdd_issues_split_by_project/`).
- Computes `time_to_resolution_days`, `comments_count`, and `issue_events_count` for each issue.
- Determines `first_issue_date` and `last_issue_date` for the entire project.
- Output: JSON files with added statistical data in `res/pdd_issues_with_stats/`.

---

### `fetch_general_projects_info.rb`
A standalone script to collect and structure issue data for general GitHub projects (not specific to XML puzzle parsing).

**Key features:**
- Reads a list of target repositories from `gh_scripts/300_selected_projects.json`.
- Fetches all closed issues created between 2023 and 2024 (up to 400 per project) via the GitHub API.
- Retrieves comments, events, and project-level metadata (stars, forks, language, contributors).
- Replicates the exact structure found in `res/pdd_issues_with_stats/` but omits PDD-specific fields like `ticket`, `file`, and `lines`.
- Calculates statistical fields (`time_to_resolution_days`, `comments_count`, etc.).
- Includes a checkpointing system (`.checkpoint.json`) and rate limit sleep mechanism to safely process long lists of projects.
- Output: JSON files in `res/general_gh_project_info/`.

---

### `parser_json_for_xml.rb`
Groups puzzles from an XML-derived JSON file into time-windows centered around closed puzzles.

**Key features:**
- Reads `results/dataset_from_xml.json`.
- Defines time windows `[data_start, data_end]` for each repo based on "anchor" closed puzzles.
- Keeps collections with more than one puzzle.
- Output: `dataset_xml_by_timestamps.json`.

---

### `parser_to_chronographic.rb`
Normalizes and re-indexes puzzle collections chronologically to simplify LLM or survey usage.

**Key features:**
- Reads `results/dataset_xml_by_timestamps.json`.
- Strips unnecessary fields, leaving: `id`, `created_at`, `body`, `file`, and `lines`.
- Sorts puzzles by creation date.
- Adds `days_since_first_puzzle` field.
- Output: `dataset_simple_chronographic.json`.

---

### `parser_json_group_by_repos.rb`
An alternative grouping script for non-XML datasets (e.g., `dataset.json`).

**Key features:**
- Groups puzzles by repository and time-windows.
- Filters only comment-rich puzzles.
- Output: `dataset_group_by_repos.json`.

---

## Prompt Makers

These scripts convert the parsed dataset into prompts for LLMs or human evaluation.

### `prompt_maker.rb`
- **Source**: `dataset_xml_by_timestamps.json`
- **Goal**: LLM prioritization task.
- **Prompt**: Lists issues and asks the model to pick the highest priority `id` without reasoning.
- **Output**: `prompts_for_long_explaining.json` (Includes `prompt` and `answer`).

### `prompt_maker_for_survey.rb`
- **Source**: `results/dataset_simple_chronographic.json`
- **Goal**: Human or LLM surveys.
- **Prompt**: Lists issues in chronological order (up to 6 per set).
- **Output**: `prompts_survey.json`.

## Workflows

This repository is organized logically into sequentially numbered workflow directories that parse, group, format, and evaluate PDD puzzles and general dataset metrics.

### [Workflow 0: Extract PDD Issues](workflows/0_extract_pdd_issues_from_xml/README.md)
Handles the primary data parsing out of RAW `0pdd` xml outputs using `1_parser_xml.rb`.

### [Workflow 1: Basic XML to Prompts](workflows/1_basic_xml_to_prompts/README.md)
Translates the basic raw XML parsed output, sorts it chronologically, groups it by boundaries, and builds the prompts directly for LLM evaluation.

### [Workflow 2: Enrich and Split PDD Issues](workflows/2_enrich_and_split_pdd_issues/README.md)
Expands upon the basic XML lists by mapping directly to GitHub APIs grabbing comment bodies, label information, and time tracking resolutions. Groups projects out individually and builds aggregated calculation records per project.

### [Workflow 3: Alternative Non-XML Pipeline](workflows/3_alternative_non_xml_pipeline/README.md)
Alternative grouping processes specifically for JSON imports skipping the XML interpretation stage entirely.

### [Workflow 4: Survey Prompt Generation](workflows/4_survey_prompt_generation/README.md)
Prepares arrays of output specific to human evaluation usage via cronologically organized surveys.

### [Workflow 5: General Projects Collection](workflows/5_general_projects_collection/README.md)
Fetches and aggregates non-puzzle associated tasks locally leveraging native GitHub APIs for comparative general GitHub datasets.

### [Workflow 6: Compute Project Metrics](workflows/6_compute_project_metrics/README.md)
Independent metric evaluation suite computing body lengths, label presence rates without `pdd` matching, and closure times per repository target directory.

> [!NOTE]
> Some scripts expect input files in specific directories (e.g., `res/` or `results/`). Please see the respective workflow's README for more detail.
